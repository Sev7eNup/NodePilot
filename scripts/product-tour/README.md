# NodePilot product tour

Records the actual React frontend with fictional, isolated API fixtures. Produces a silent English product tour, a short GIF and a poster. An opening scene shows SCOrch import, its review modal and the converted workflow. The main workflow combines service management, PowerShell, File Copy and an LLM summary. AI Chat uses a deterministic local response fixture. It does not start workflows, use stored login sessions, contact target machines or an LLM, or publish anything.

## Capture

Requires the UI's installed npm dependencies, its matching Playwright Chromium, and Node 22.22 or newer. Start the local UI with `npm run dev` from `src/nodepilot-ui` if it is not running. The backend is not needed.

From the repository root:

```powershell
node --experimental-strip-types scripts/product-tour/record.mjs --preview
node --experimental-strip-types scripts/product-tour/record.mjs
python scripts/product-tour/render.py
```

The optional preview checks the click sequence and captures stills without recording video. The real capture records lossless PNG frames through Chromium's CDP screencast API and retains elapsed frame timestamps for pauses and animations. The renderer requires FFmpeg with libx264 and GIF filters; set the `FFMPEG` environment variable to its executable, put it on PATH, or install `imageio-ffmpeg`. The renderer also looks for that package in `.tmp/nodepilot-video/tools`.

`TOUR_BASE_URL` defaults to `http://localhost:5173` and must use loopback. `TOUR_OUTPUT` defaults to the git-ignored `out/product-tour-liveops-v2`, keeping the earlier exports in `out/product-tour` and its version archives. A fresh browser context intercepts API requests and rejects unexpected mutations; only local frontend assets may load. Accepted POSTs are limited to the fixed demo question to the locally mocked AI knowledge stream and the exact bytes of `fixtures/Daily-Log-Archive.ois_export` to the mocked SCOrch import. The hostnames, user, workflow history and statistics are all fictional. The existing browser profile and database are not accessed.

The import fixture contains three activities: Initialize Data, Copy File and Run .Net Script. `fixtures/import-result.json` was generated by the actual `NodePilot.Engine.Scorch.ScorchImporter.Parse` method from this file. Its converted definition and warnings are retained in the demo response; only persistence and the returned workflow ID are mocked. Playwright handles the browser file chooser; the video captures the application, including the selected filename in the result modal.

## Review and export

Open `out/product-tour-liveops-v2/Ansehen.html` after rendering. The result is approximately 84 seconds, captured natively at 2560 × 1440 and exported as H.264/yuv420p, CRF 15, 30 fps, without audio. The application is shown at 88% of its original relative size, exposing more content. A smaller 1920 × 1080 MP4 is also exported. Captions and the demo-data label are part of the video. The 20-second GIF is a condensed overview at 960 × 540.

The capture checks the graph, File Copy settings, Monaco editor and English AI label, Gantt chart, step output, execution drilldown, structured/plain-text logs, global AI Chat and AI/identity settings. The editor scene ends about 3.5 seconds after Monaco opens; it is not padded to the scene's maximum duration. The dashboard scroll lasts 4 seconds. Identity settings are marked as Preview, consistent with the project documentation. Inspect `capture.json` for actual scene durations, browser errors and endpoints served by the shared empty/default UI fixtures. The renderer decodes both finished MP4s and checks their duration and frame count, writing validation status to `export.json`. Review screenshots and video visually as well. Use `python scripts/product-tour/render.py --verify-only` to recheck existing exports.

The eleven sets of PNG frames, concat timelines, stills and render logs live in `out/product-tour-liveops-v2/raw/`. Final media stays outside source control. The accompanying `POST-TEXT.md` is only a publication draft. The 12-second import scene is an unnumbered prelude to the existing eight chapters.

To replace one scene after a complete capture, pass e.g. `--only=04-liveops` to `record.mjs`, then render again. Keep the other raw clips from that capture.

## Vertical shorts

Two separate eight-second 1080 × 1920 films reuse this directory's tooling and are documented on their own. `SHORT.md` describes `render-short.py`, which recuts the finished tour MP4 above into a social short with a synthesized soundtrack. `DESIGNER-SHORT.md` describes `capture-designer-short.mjs`, `render-designer-short.py` and `check-designer-short.mjs`, which record a fresh Workflow Designer sequence instead of reusing tour footage. Both write to their own `out/` folders and leave the tour exports untouched.
