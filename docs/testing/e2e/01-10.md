### Test 2.14 — Weitere Activity-Typen: Dateien, Aufgaben, Warten, Text, KI, Verzweigung

Pro Typ: Node hinzufügen → Pflichtfelder setzen → Speichern → Run.

- `textFileEdit` (Remote): `operation` `append` mit `appendIfMissing: true`, `path`, `content`. Zweiter Run darf die Zeile nicht doppeln; `dryRun: true` ändert die Datei nicht.
- `scheduledTask` (Remote): `taskName`, `action` `get` (Default), danach `start`/`stop`/`enable`/`disable`.
- `fileHash` (Remote): `path`, `algorithm` `SHA256` (Default); mit `expected` vergleicht der Step und scheitert bei Abweichung.
- `zipOperation` (Remote): `operation` `compress` (Default) mit `source`/`destination`, danach `extract`; `force` steuert das Überschreiben.
- `waitForCondition` (Hybrid): `conditionType` `pathExists`, `serviceRunning`, `portOpen`, `httpOk` oder `script`, jeweils mit dem eigenen Schlüssel; `timeoutSeconds`/`intervalSeconds` begrenzen das Polling; Timeout → Step fehlgeschlagen.
- `generateText` (Engine-local): `mode`, `length`; Ergebnis ist ein Zufallsstring, **kein** LLM-Aufruf.
- `llmQuery` (Engine-local): `prompt`; mit `Llm:Enabled=false` scheitert der Step mit klarer Meldung.
- `aiAgent` / `aiAgentTeam` (Engine-local): `task` plus Agent- bzw. Team-Definition; ohne aktives LLM-Profil blockiert die Validierung.
- `decision` (controlFlow): mehrere `cases` mit `condition`; Downstream-Kanten über `{{step.param.case}}`.
- `forEach` (controlFlow): `items` plus `childWorkflowNameOrId`; Item und Index kommen im Child als `manual.*` an.

**Prüfpunkte:**
- [ ] Jeder Node wird gerendert, Pflichtfelder werden validiert, Speichern erfolgt
- [ ] Run liefert das dokumentierte Ergebnis bzw. die dokumentierte Fehlermeldung
- [ ] Die KI-Typen sind ohne aktives LLM-Profil nicht ausführbar

### Test 10.2 — Mobile Responsiveness (Smartphone/Tablet)

> Automatisiert in `e2e/mobile-responsive.spec.ts` (Kern-Guard: kein horizontaler Overflow bei 390px auf jeder Listen-Route + read-only Graph rendert Edges + KI-Chat trimmt Header/Beispiel-Prompts und bleibt scrollbar + Live-Ops zeigt die Lauf-Liste statt der Timeline). Desktop-Layout bleibt ab `lg` unverändert.

**Schritte:**
1. Öffne die SPA im Mobile-View (DevTools: 390px width)
2. Toggle die Sidebar über das Hamburger-Menü in der TopBar (Drawer + abgedunkelter Backdrop, schließt automatisch bei Navigation)
3. Öffne die Listen-Seiten (Workflows, Executions, Machines, Users, Global Variables, Maintenance Windows, Audit) — sie sollen als gestapelte Cards erscheinen, nicht als breite Tabelle
4. Öffne einen Workflow → es erscheint die **read-only** Mobile-Graph-Ansicht (`MobileWorkflowView`); teste Pan/Pinch-Zoom
5. Öffne `/ai-chat` → Untertitel, Quellen-Badge-Zeile und Intro-Satz fehlen, es stehen 4 statt 8 Beispiel-Prompts (Platz für die Konversation); der Empty-State beginnt mit Icon + Überschrift und lässt sich auch auf einem kurzen Screen vollständig scrollen
6. Öffne `/operations` → statt der Timeline erscheint die Lauf-Liste (Zähler-Zeile, Hängende, Fehlgeschlagene in eigener Box, Laufende, gerade beendet), Workflow-Namen vollständig; Tap auf einen Lauf öffnet den Drilldown als Vollbild-Sheet mit denselben Aktionen; das Departure-Board stapelt Zeit/T-minus über den Namen

**Prüfpunkte:**
- [ ] Sidebar-Drawer öffnet/schließt korrekt (Hamburger + Backdrop, Auto-Close bei Navigation)
- [ ] Kein horizontaler Scroll/Overflow auf den Listen-Seiten bei 390px (Cards statt Tabelle)
- [ ] Workflow öffnet als read-only Graph mit Live-Execution-Status (kein Editieren/Node-Erstellung auf Mobile)
- [ ] Pan/Pinch-Zoom funktioniert; kein Crash
- [ ] KI-Chat bei 390px: kein Untertitel, keine Quellen-Badges, kein Intro-Satz, 4 Beispiel-Prompts, Empty-State oben nicht abgeschnitten (ab `lg` ist alles wieder da, 8 Prompts)
- [ ] Live-Ops bei 390px: keine Timeline, sondern Lauf-Liste mit vollen Namen und tickender Laufzeit; fehlgeschlagene Läufe stehen in einer eigenen Box über den laufenden (nicht in „gerade fertig“ vergraben); Drilldown-Sheet inkl. Abbrechen/Erneut/Quarantäne erreichbar; ab `lg` wieder Timeline

**Erwartung:** SPA voll nutzbar auf dem Smartphone; Designer-Editing bleibt Desktop-only (≥ `lg`).
