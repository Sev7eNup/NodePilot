# CM1 log review after audit deployment (2026-10-09)

Scope: all retained NodePilot main logs (2026-10-05 through 2026-10-09) and support logs (2026-09-16 through 2026-10-09), retained SQL Server ERRORLOG files, Windows Application/System events since 2026-10-05, and WinRM, Task Scheduler, PowerShell Operational and Windows PowerShell channels. The VM's file logs use a Pacific local clock; the Windows event viewer on the client displays Berlin local time. Findings below use dates rather than ambiguous local clock times.

## Current state

- `NodePilot` and `MSSQLSERVER` are running; `https://localhost:8443/healthz/ready` returned 200.
- On 2026-10-09 the NodePilot main log contains no error-level message outside `[TestSuite]`. Its error-level records are deliberate `USER-LOG ... log: error` test messages. No retained support log has an `[ERROR]` or `[FATAL]` line.
- No NodePilot service crash or service-account logon failure appears after the current deployment. The current SQL ERRORLOG has no error-like line on 2026-10-09. WinRM Operational has no warning/error since 2026-10-05.
- The completed CM1 smoke test is in `cm1-smoke-20261009.md`.

## Findings to keep in view

1. **Credential exposure in PowerShell diagnostics (security, actionable).** Eleven PowerShell Operational event 4104 records on 2026-10-09 contain the test admin account's password from our remote verification scriptblocks. The password is deliberately not copied into this report. These events should remain available as evidence, but the test account password should be rotated and future verification should avoid literal credentials in remotely logged scriptblocks. Separately, `C:\ProgramData\NodePilot\appsettings.runtime.json` contains a nonempty LLM profile API key in plaintext. Its file ACL is limited to SYSTEM, Administrators and the NodePilot service account; nonetheless the boot security warning is genuine and a secrets provider or protected injection would reduce at-rest exposure.
2. **Expected missed triggers during the deployment window.** Five schedule-trigger warnings each report one missed tick; the Event Log trigger reports two skipped Application-log entries while NodePilot was stopped. The current implementation intentionally does not replay entries written during downtime. Later trigger-suite runs passed.
3. **Historical Event Log read failures.** Eighty-two error records from 2026-10-05 through 2026-10-07 show `EventLogInternal.GetCachedEntryPos` throwing `IndexOutOfRangeException` while reading a changing Windows log. The current source catches this as a transient read failure and retries from the stored cursor. No such error appears in the 2026-10-08/09 main logs, and the live Event Log trigger tests passed.
4. **Historical SQL performance failures.** Five EF commands timed out at the 120-second limit between 2026-10-05 and 2026-10-08, including execution-statistics rollups. No recurrence appears on 2026-10-09. EF emitted two multiple-collection-query warnings shortly after the deployment; these are a possible performance risk, not evidence of a current timeout.
5. **Historical infrastructure faults.** Windows System has five groups of NodePilot service logon/start/termination errors on 2026-10-07 while the domain could not be contacted; none recur after that date. SQL Server ERRORLOG.5 contains a brief 2026-10-04 memory-pressure burst (29 error 701 entries and many 17300/17312 diagnostics). Other archived SQL errors mostly concern `ConfigMgr_CHQ` logins, not the current NodePilot database. Task Scheduler's recent errors concern Windows Update's `USO_UxBroker`; the one NodePilot test-task warning was a queued test instance, and no test task remains.
6. **Log noise.** The retained main logs contain roughly 385,000 repeated warnings about ambiguous `firedAt`/`nextFireAt` PowerShell parameter aliases, overwhelmingly from test-suite workflows; the four largest message groups each occur 96,350 times. The warnings describe the intentional requirement to qualify duplicated names, but their volume consumes log space and makes unrelated warnings harder to find. The main logs occupy hundreds of megabytes over five days.

PowerShell Operational also contains WSMan/runspace diagnostic events during administration. They were not accompanied by WinRM Operational errors or a NodePilot service failure in this review. No Windows event log was cleared.
