# NodePilot.Mcp (`nodepilot-mcp`) — Conventions

Applies to `src/NodePilot.Mcp/`. Project-wide rules are in the root `CLAUDE.md`.

Pure HTTP client against the REST API (like the CLI) + in-proc analysis against `NodePilot.Core` — **no** new backend path (116 tools, 3 resources), stdio transport; reuses the CLI's DPAPI session (`np auth login`). Destructive tools (`delete_*`, `force_unlock_workflow`, `cancel_all_executions`, `restart_service`, `test_step`) are registered only when `NODEPILOT_MCP_ALLOW_DESTRUCTIVE=true`; workflow definitions are secret-redacted before tool output, and on publish/patch real secrets are restored from the stored version. Full docs: `docs/mcp-server.md`.

**Architecture convention:** New API endpoint → method in `Api/NodePilotApiClient.cs` (DTOs duplicated in `Api/Dtos/`) + `[McpServerTool]` method in the matching `Tools/*Tools.cs` (destructive → maintain `DestructiveTools` + the `get_safety_status` list), register the class in `Program.cs` via `WithTools<T>()` if needed (**never** `WithToolsFromAssembly`), add a WireMock test. Frontend data-bus/lint logic is **not** mirrored here but in `NodePilot.Core.WorkflowDefinitions` (`WorkflowAnalyzer` + `WorkflowDataBusAnalyzer`, mirror of `workflowLint.ts`/`upstreamVariables.ts`) — it serves MCP **and** the AI chat, guard `WorkflowAnalyzerFrontendParityTests` (Engine.Tests). The layout lives there for the same reason: `WorkflowLayoutEngine` (+ `WorkflowLayoutOptions`) in `NodePilot.Core.WorkflowDefinitions` serves `suggest_layout` **and** the SCOrch import, which must not reference `NodePilot.Mcp` per the dep graph — `WorkflowLayoutOptions.Compact` keeps the MCP output unchanged. Only `DefinitionDiff` remains in `Analysis/`.

**Shared client infrastructure:** `ApiException`, the response plumbing (`ApiResponseReader`), the read side of `config.json` (`ClientConfigStore` + `CliConfig`), the DPAPI session store and token rotation (`TokenStore`, `StoredSession`, `TokenRefreshHandler`) as well as the TLS layer (`CertificatePin`, `ClientTlsOptions`, `PinnedCertificateHandlerFactory`, `TlsObservationHandler`, `NetworkFailureAnalyzer`) live in `NodePilot.Core.Clients` — shared with the CLI. **Only the DTOs remain duplicated on purpose** (`Api/Dtos/`); do not copy new infrastructure again (guard: `CliSessionInteropTests`).

**Activity config reference:** lives **not** under `Resources/Embedded/` but in `NodePilot.Core` (`Activities/Embedded/activity-config-reference.json`, read via `ActivityConfigReference`) — `NodePilot.Ai` renders the activity catalogue of the AI prompts from it. Maintain new/changed config keys there; `ActivityConfigReferenceTests` checks that every documented key is actually read by the executor.
