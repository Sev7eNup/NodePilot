In einem gewachsenen SCOrch-Runbook steckt viel Arbeit. Neben der Reihenfolge der Aktivitäten und der Fehlerbehandlung legen Bedingungen fest, welchen Pfad eine Ausführung nimmt. Hinzu kommen die Daten, die von einer Aktivität an die nächste weitergereicht werden. Diese Zusammenhänge sollten bei einer Migration nicht von Hand rekonstruiert werden müssen.

Mit dem vorhandenen Export starten

Ausgangspunkt ist der vorhandene SCOrch-Export, den NodePilot im Format .ois_export einliest. Der Import lässt sich über die Oberfläche oder die CLI starten:

np workflow import-scorch --file .\runbooks.ois_export

NodePilot übersetzt unterstützte Aktivitäten in passende Aktivitäten des eigenen Workflow-Modells. Dabei berücksichtigt der Import auch Verbindungen und Bedingungen sowie globale Variablen und Published-Data-Verweise, über die nachfolgende Schritte auf Daten zugreifen. Auch die Ordnerstruktur lässt sich übernehmen.

Ein Importbericht ist Teil des Ergebnisses

Nicht jede Aktivität und jede Eigenschaft ist verlustfrei übertragbar. An die Stelle einer nicht unterstützten Aktivität tritt deshalb ein deaktivierter Platzhalter, zu dem der Importbericht die relevanten Informationen aufführt.

Besondere Aufmerksamkeit verdienen Zielsystemangaben, die unvollständig geblieben sind, sowie Datenreferenzen, die sich nicht übersetzen ließen. Auch Zeitpläne können nur näherungsweise übertragen worden sein. Nach dem Import muss geprüft werden, ob der übernommene Workflow weiterhin wie vorgesehen arbeitet.

Vor der Aktivierung prüfen

Importierte Workflows bleiben zunächst deaktiviert. Der Import rekonstruiert keine Zugangsdaten aus den verschlüsselten SCOrch-Daten. Vor der Aktivierung sollten deshalb die Hinweise, die der Bericht aufführt, ebenso kontrolliert werden wie Zielsysteme, Berechtigungen und Fehlerpfade.

Anschließend folgt ein Test in einer geeigneten Testumgebung. Der Workflow wird erst ausdrücklich aktiviert, wenn sein Verhalten den eigenen Anforderungen entspricht.

Die Entscheidungen zur Migration bleiben bei den Verantwortlichen. Als Grundlage liefert der Import das tatsächliche Runbook und einen nachvollziehbaren Bericht.
